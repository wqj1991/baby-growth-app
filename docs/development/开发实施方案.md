# 宝宝成长记录 APP 开发实施方案（Android + HarmonyOS）

---

## 1. 总览

### 1.1 项目目标
- 使用uni-app x开发, 打包为交 Android 与 HarmonyOS 两套客户端。
- 无自建服务器：**Phase 1** 以本地存储实现完整功能闭环；**Phase 2** 整体切换为夸克网盘同步与备份，业务代码零改动。

### 1.2 实施范围（对应 PRD）
- 启动授权、共享账号登录、家庭空间初始化。
- 影像链路：拍照/录像、本地上传、缓存预览、手动下载。
- 育儿记录：喂养/大小便/睡眠/健康记录。
- 同步链路（Phase 2）：进页面拉配置、下拉刷新、10 分钟自动同步、离线补传。
- 设置与安全：缓存配置、下载路径、日志与配置加密。

### 1.3 明确边界
- Phase 2 夸克网盘仅使用：文件上传 / 下载 / 目录管理。
- 冲突策略：Last Write Wins（最后写入覆盖）。
- 加密边界：仅日志与配置文件加密，媒体文件不加密。

### 1.4 代码组织（Monorepo）
```
baby-growth-app    ← uni-app x 客户端
docs/requirements  ← 需求文档
docs/ux            ← 高保真原型
```

### 1.5 共享与差异划分
- **共享规则**：数据模型、同步协议、冲突策略、缓存规则、加密规范。
- **平台实现**：通过 uni-app x 的原生扩展能力调用特定平台的 API，如权限系统、相机/相册、文件系统、后台任务等。

## 2. UI 开发实施方案

整体思路先开发 UI，再开发交互，使用 uni-app x 做开发框架。

### 2.1 UI 库选型
- **唯一 UI 组件库**: `uni-ui X`（官方）
- **业务层实现方式**: 基于 `uni-ui X` + `uni-app x` 基础视图组件封装项目内业务组件

本项目不再引入第三方 UI 库。基础控件统一使用官方组件，业务卡片、时间线、宫格、统计块等由项目内部封装，保证风格统一、依赖可控、双端适配风险最低。

### 2.3 UI 开发规则
1.  **基础控件优先用 uni-ui X**：如导航栏、Tabbar、按钮、输入框、选择器，保证双端系统级适配。
2.  **复杂业务块统一项目内封装**：卡片、时间线、宫格、统计模块全部在项目内基于官方组件二次封装，不依赖第三方 UI。
3.  **图表能力单独实现**：统计页 Phase 1 先完成筛选、汇总卡片和基础趋势占位，后续如必须图表化，优先采用项目内自绘组件，不新增 UI 依赖。
4.  **依赖保持最小化**：UI 层仅使用官方 `uni-ui X`，避免样式冲突、包源不稳定和后期维护成本增加。
5.  **Flex 布局方向明确**：uni-app x 中以下组件默认为 `flex-direction: column`（竖向排列），如需横向排列必须显式添加 `flex-direction: row`：

## 3. 架构设计

### 2.1 核心设计原则

| 原则 | 说明 |
|------|------|
| **存储无关** | 所有业务逻辑只依赖抽象接口，不直接访问文件系统或网盘 SDK |
| **目录镜像** | 本地目录结构与夸克网盘目录结构完全对齐，切换时无需重组数据 |
| **离线优先** | 写入永远先落本地，同步为后置动作（Phase 2 才有意义） |
| **加密边界一致** | 本地与云端采用同一套加密字段和算法，Phase 2 直接复用 |

### 2.2 存储抽象层（Storage Abstraction Layer）

#### 核心接口

```
IStorageProvider
├── IConfigStorage      // 应用配置 & 宝宝档案
├── ILogStorage         // 结构化育儿日志
├── IMediaStorage       // 媒体文件 & 元数据
└── ISyncQueueStorage   // 同步任务队列（Phase 1 仅本地持久化）
```

```kotlin
// Android 示例（Harmony ArkTS 结构对等）
interface IConfigStorage {
    suspend fun readConfig(): AppConfig
    suspend fun writeConfig(config: AppConfig)
    suspend fun readBabyProfile(): BabyProfile
    suspend fun writeBabyProfile(profile: BabyProfile)
}

interface ILogStorage {
    suspend fun insertLog(log: CareLog): String
    suspend fun queryLogs(filter: LogFilter): List<CareLog>
    suspend fun updateLog(log: CareLog)
    suspend fun deleteLog(logId: String)
}

interface IMediaStorage {
    suspend fun saveRawMedia(file: LocalFile): MediaItem
    suspend fun savePreview(mediaId: String, thumb: ByteArray)
    suspend fun queryMedia(filter: MediaFilter): List<MediaItem>
    suspend fun deleteMedia(mediaId: String)
    fun getCacheSizeBytes(): Long
    suspend fun clearPreviewCache(olderThanDays: Int = 7)
}

interface ISyncQueueStorage {
    suspend fun enqueue(task: SyncTask)
    suspend fun dequeue(limit: Int = 20): List<SyncTask>
    suspend fun markDone(taskId: String)
    suspend fun markFailed(taskId: String, reason: String)
}
```

#### Phase 1 实现 — LocalStorageProvider

```
LocalStorageProvider
├── LocalConfigStorage      → 加密 JSON 文件
├── LocalLogStorage         → SQLite（baobao.db，care_logs 表）
├── LocalMediaStorage       → 文件系统 + SQLite（media_items 表）
└── LocalSyncQueueStorage   → SQLite（sync_tasks 表，Phase 1 立即标记为 DONE）
```

#### Phase 2 实现 — QuarkStorageProvider

```
QuarkStorageProvider
├── QuarkConfigStorage      → 网盘 /Baby/Config/ 加密文件
├── QuarkLogStorage         → 网盘 /Baby/Logs/{year-month}/ 加密 JSON
├── QuarkMediaStorage       → 网盘 /Baby/Media/raw/ + /Baby/Media/preview/
└── QuarkSyncQueueStorage   → 本地 SQLite（队列本身永远在本地）
```

> Phase 2 只需在 DI 容器中将注入实现从 `Local*` 替换为 `Quark*`，业务层无感知。

### 2.3 本地目录结构

```
[AppPrivateDir]/              ← Android: filesDir  |  Harmony: getContext().filesDir
├── Baby/
│   ├── Config/
│   │   ├── app_config.enc    ← AppConfig（AES-256-GCM 加密）
│   │   └── baby_profile.enc  ← BabyProfile（AES-256-GCM 加密）
│   └── Logs/
│       ├── 2025-04/
│       │   └── logs.enc      ← 当月 CareLog 列表（AES-256-GCM 加密）
│       └── 2025-05/
│           └── logs.enc
│
├── db/
│   └── baobao.db             ← SQLite：care_logs / media_items / sync_tasks
│
├── media/
│   ├── raw/                  ← APP 专属相册真实文件（拍摄写入此处，注册媒体库）
│   │   ├── {mediaId}.jpg
│   │   └── {mediaId}.mp4
│   └── preview/              ← 预览缩略图缓存（不注册媒体库，可自动清理）
│       └── {mediaId}_thumb.jpg
│
└── cache/                    ← 其他临时缓存（Phase 2：网盘预览缓存落此处）
```

#### 本地与夸克目录映射关系

| 本地路径 | 夸克网盘路径 | 切换动作 |
|---------|------------|---------|
| `Baby/Config/app_config.enc` | `/Baby/Config/app_config.enc` | 直接上传，路径不变 |
| `Baby/Config/baby_profile.enc` | `/Baby/Config/baby_profile.enc` | 直接上传，路径不变 |
| `Baby/Logs/{month}/logs.enc` | `/Baby/Logs/{month}/logs.enc` | 直接上传，路径不变 |
| `media/raw/{mediaId}.*` | `/Baby/Media/raw/{mediaId}.*` | 上传原文件 |
| `media/preview/{mediaId}_thumb.*` | `/Baby/Media/preview/{mediaId}_thumb.*` | 可重新生成或上传 |

### 2.4 三类媒体管理规则

| 类别 | 来源 | 本地路径 | 注册媒体库 | 可清理 |
|------|------|---------|-----------|-------|
| **本地实拍** | APP 内置相机 | `media/raw/` | ✅ 专属相册 | ❌ 用户主动删除 |
| **云端缓存预览** | Phase 2 网盘缩略图 | `media/preview/` | ❌ | ✅ 自动 7 天 / 手动清空 |
| **手动下载** | 用户主动下载 | 用户选择路径 | ✅ 专属相册或系统相册 | ❌ 用户主动删除 |

### 3.6 SQLite 表结构

```sql
-- 育儿日志
CREATE TABLE care_logs (
    id TEXT PRIMARY KEY,
    type TEXT NOT NULL,
    baby_id TEXT NOT NULL,
    recorded_at INTEGER NOT NULL,     -- Unix 毫秒
    recorded_by TEXT NOT NULL,
    data TEXT NOT NULL,               -- JSON
    note TEXT,
    media_ids TEXT,                   -- JSON 数组
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    deleted INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_care_logs_baby_time ON care_logs(baby_id, recorded_at DESC);
CREATE INDEX idx_care_logs_type ON care_logs(type, baby_id, recorded_at DESC);

-- 媒体元数据
CREATE TABLE media_items (
    id TEXT PRIMARY KEY,
    type TEXT NOT NULL,
    source TEXT NOT NULL,
    local_raw_path TEXT,
    local_preview_path TEXT,
    cloud_raw_path TEXT,
    file_size_bytes INTEGER,
    duration_seconds INTEGER,
    captured_at INTEGER NOT NULL,
    uploaded_at INTEGER,
    baby_id TEXT NOT NULL,
    taken_by TEXT NOT NULL,
    deleted INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_media_items_baby_time ON media_items(baby_id, captured_at DESC);

-- 同步任务队列
CREATE TABLE sync_tasks (
    id TEXT PRIMARY KEY,
    action TEXT NOT NULL,
    resource_type TEXT NOT NULL,
    resource_id TEXT NOT NULL,
    local_path TEXT,
    remote_path TEXT,
    status TEXT NOT NULL DEFAULT 'PENDING',
    retry_count INTEGER NOT NULL DEFAULT 0,
    error_message TEXT,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
CREATE INDEX idx_sync_tasks_status ON sync_tasks(status, created_at ASC);
```

### 3.7 加密规范

| 项目 | 规格 |
|------|------|
| 算法 | AES-256-GCM |
| 密钥存储 | Android Keystore / HarmonyOS HUKS |
| 加密范围 | `app_config.enc`、`baby_profile.enc`、`logs.enc` |
| 不加密 | SQLite 文件本身（使用系统 AppPrivateDir 隔离）、媒体文件 |
| Phase 2 一致性 | 云端存储格式与本地加密格式完全相同，上传即可，无需重新加密 |

## 5. 模块设计

### 4.1 模块依赖关系

```
┌─────────────────────────────────────────────────────────┐
│                      UI Layer                           │
│  HomeFragment  RecordFragment  StatsFragment  MineTab   │
└──────────────────────┬──────────────────────────────────┘
                       │ 调用 ViewModel / UseCase
┌──────────────────────▼──────────────────────────────────┐
│                  Domain Layer                           │
│   CareLogUseCase  MediaUseCase  ConfigUseCase           │
│   SyncUseCase (Phase 1: no-op  | Phase 2: real sync)    │
└──────────────────────┬──────────────────────────────────┘
                       │ 依赖抽象接口
┌──────────────────────▼──────────────────────────────────┐
│              Storage Abstraction Layer                  │
│   IConfigStorage  ILogStorage  IMediaStorage            │
│   ISyncQueueStorage                                     │
└──────────┬──────────────────────────────┬───────────────┘
           │ Phase 1                      │ Phase 2
┌──────────▼───────────┐    ┌─────────────▼──────────────┐
│  LocalStorageProvider │    │  QuarkStorageProvider      │
│  (文件系统 + SQLite)   │    │  (夸克 SDK + 本地 SQLite)  │
└──────────────────────┘    └────────────────────────────┘
```

### 4.2 Auth 模块
- 共享账号登录态管理。
- 启动授权流程编排（相机/相册/存储/通知权限）。

### 4.3 Media 模块
- 内置拍摄：本地专属相册落盘，注册媒体库。
- 本地上传：仅写入元数据 + 入同步队列，不改动原图。
- 浏览：优先 `media/preview/` 缓存预览，禁止自动下载原文件。
- 下载：用户主动触发，默认保存专属相册，可改保存路径。

### 4.4 CareLog 模块
- 喂养、排泄、睡眠、健康全类型记录录入与查询。
- 本地暂存（SQLite），Phase 2 联网同步。

### 4.5 Sync 模块（Phase 2 生效）
- 触发器：进入页面、下拉刷新、10 分钟定时。
- 任务队列：待上传、待下载、失败重试（退避策略）。
- 断网恢复：自动补传与增量刷新。
- 冲突处理：Last Write Wins（`updatedAt` 比较）。

### 4.6 Settings 模块
- 缓存上限（默认 2 GB）、自动清理周期（默认 7 天）。
- 下载目录配置与手动清理动作。

### 4.7 Security 模块
- AES-256-GCM 加解密工具。
- 密钥安全存储（Android Keystore / HarmonyOS HUKS）与轮换策略预留。

## 9. CSS 兼容性注意事项

### 9.1 不支持的 CSS 属性

| 属性/选择器 | 状态 | 替代方案 | 影响文件 |
|------------|------|----------|----------|
| `overflow: revert` | ❌ 不支持 | 使用 `overflow: visible` | `pages/home/index.uvue`<br>`pages/profile/index.uvue`<br>`pages/record/index.uvue` |
| `gap` | ❌ 不支持 | 使用子元素的 `margin` 属性替代 | `pages/record/index.uvue`<br>`pages/profile/index.uvue` |
| `aspect-ratio` | ❌ 不支持 | 使用固定的 `width` 和 `height` 值替代 | `pages/record/index.uvue` |
| `:not(:last-child)` 伪类 | ❌ 不支持 | 在子元素类上直接添加 margin（接受最后一个元素也有margin的微小视觉差异） | `pages/record/index.uvue`<br>`pages/profile/index.uvue` |
| `calc()` 函数 | ❌ 不支持 | 使用固定像素值或百分比替代 | `pages/record/index.uvue`<br>`pages/timeline-video-detail.uvue`<br>`pages/timeline-photo-detail.uvue` |
| 复合 padding 中的 `calc()` | ❌ 不支持 | 拆分为独立的 `padding-top`、`padding-left`、`padding-right`、`padding-bottom` 属性 | `pages/timeline-video-detail.uvue`<br>`pages/timeline-photo-detail.uvue` |

### 9.2 样式开发建议

1. **避免使用现代 CSS 属性**：HBuilder 编译时对部分现代 CSS 属性支持有限，优先使用基础 CSS 属性。

2. **Flex 布局间距处理**：
   - 避免使用 `gap` 属性
   - 使用子元素的 `margin-right`（横向排列）或 `margin-bottom`（纵向排列）实现间距
   - 接受最后一个元素也有 margin 的微小视觉差异，或通过额外类名控制最后一个元素

3. **宽高比处理**：
   - 避免使用 `aspect-ratio` 属性
   - 使用固定的 `width` 和 `height` 值
   - 或使用百分比 + 固定像素值组合

4. **伪类选择器限制**：
   - 避免使用复杂伪类选择器如 `:not()`、`:last-child`、`:first-child` 等
   - 使用直接类选择器替代

5. **calc() 替代方案**：
   - 使用固定像素值替代动态计算
   - 或使用百分比值
   - 对于安全区域适配，直接使用 `env(safe-area-inset-bottom)` 而不嵌套在 `calc()` 中
